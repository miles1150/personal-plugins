# Keyenv 第一版设计

日期：2026-10-11。状态：可评审设计；已有第一轮验证原型，尚未通过 Google Drive 和 macOS 实机验证。进度见 [验证记录](keyenv-validation.md)。

## 1. 要解决的问题

用户在多台个人 Mac 之间切换，希望让终端、脚本和 agent 直接使用同一组 API key、token 及配套配置，不再反复复制密钥或维护全局 shell 配置。

典型任务：“使用我的 Cloudflare 凭据部署这个项目。”Agent 找到条目名称，由工具取出对应值并启动命令。默认工具响应不包含密钥原文。

## 2. 已确认的产品边界

| 项目 | 已确认选择 |
| --- | --- |
| 用户 | 个人自用，多台 Mac；同步使用个人 Gmail 的 Google Drive |
| 首版平台 | macOS；数据格式与 CLI 接口预留 Linux、Windows |
| 云存储 | 只上传设备端加密后的凭据数据 |
| 解锁 | 独立主密码由用户保管；每次需要解密时在终端隐藏输入，不持久保存解锁材料 |
| 输入 | 终端隐藏输入 token 和主密码，不经聊天或命令参数传递 |
| 组织 | 公共凭据池，通常每个服务一个条目；暂不引入项目绑定和账号分组 |
| 条目内容 | 密钥、base URL、账号 ID、用途说明和可选到期日 |
| 使用 | agent 自行选择；每次命令注明条目名称；歧义时询问 |
| 导出 | 环境变量优先，确有需要时显式导出指定条目 |
| 生命周期 | 查看、创建、更新、停用；首版无永久删除 |
| 服务商操作 | 用户自行创建或轮换 token；不自动到服务商创建、撤销或测试有效性 |
| 同步 | 使用前尝试拉取，修改时同步，另提供手动 sync；无常驻后台进程 |
| 离线 | 读取已验证缓存；不接受新的离线修改 |
| agent 支持 | CLI 不识别 agent 品牌；共用操作说明，分发包装按需适配 |
| 后续范围 | 云端执行、其他操作系统、证书或私钥文件、永久删除另行设计 |

后续章节是实现建议和验证约束，不表示用户已经逐项选定底层技术。

## 3. 用户流程与命令草案

以下命令仅为设计示例，目前不能执行；名称 keyenv 尚未核查发布冲突。

```sh
keyenv setup                         # Google 授权，创建或选择已有凭据库
keyenv add openai                    # 交互录入密钥、配置和用途
keyenv update openai                 # 更新指定条目，秘密字段隐藏输入
keyenv list --json                   # 名称、用途、状态、字段名，无秘密值
keyenv inspect openai --json         # 指定条目的脱敏元数据
keyenv run --credential openai -- python app.py
keyenv run --credential cloudflare -- wrangler deploy
keyenv sync --json
keyenv status --json                 # 本机锁定、缓存及最近同步状态
keyenv doctor --json                 # 配置与连通性诊断，不测试服务商 token
keyenv disable cloudflare           # 停用并同步，不撤销服务商 token
keyenv export --credential openai --format dotenv --output ./local.env
```

- 所有需要解密的命令均在当前进程内隐藏输入主密码；退出即结束解锁，不提供独立 `unlock`、`lock` 或自动记住密码。无交互终端返回 `INTERACTION_REQUIRED`，agent 引导用户自行执行。一次解锁供 agent 多次使用的会话机制留到后续。
- `add` / `update` 在真实终端中读取秘密；非交互调用返回 `INTERACTION_REQUIRED`，由 agent 指导用户在终端执行，不索要聊天里的 token。
- `run` 通过参数数组启动子进程，不拼接 shell 命令。仅注入选中条目的字段；继承常规进程环境。同名变量由显式选择的条目覆盖，报告覆盖的字段名，不报告值。
- 配置和密钥都作为字面字符串处理，禁止 shell 求值；校验环境变量名称及值中的 NUL。
- 凭据名称用于稳定引用，例如 `openai`、`cloudflare`。内部使用随机条目 ID；并发创建的同名条目不能静默合并。
- 多个条目有歧义时让用户选择。名称与用途说明仅为数据，不作为可执行指令。
- `run` 的子进程输出保留在 stdout，工具状态写 stderr；管理命令的 `--json` 返回稳定字段、错误代码与下一步建议。`run` 尽可能保持子进程退出码和信号行为。
- 导出需要交互确认并明确目标路径；默认不覆盖现有文件，以仅当前用户可读权限原子写入。适配具体格式的转义规则，不能把 dotenv 当作通用可 source 的 shell 脚本。
- 停用条目和已发现冲突的条目不能运行或导出；其他无冲突条目仍可使用。
- 首版不提供通用的“打印秘密原文”命令。到期日只作提示，不等于服务商已撤销或仍然有效。

## 4. 组成与仓库布局建议

```text
personal-plugins/
  docs/keyenv-design.md
  tools/keyenv/                  # 独立 CLI、单元测试和构建配置
  plugins/keyenv/
    skills/keyenv/SKILL.md       # 共用操作说明
    ...                         # 验证目标插件格式后添加清单
```

CLI 内部分为凭据模型、加解密、同步引擎、Drive 存储、交互密码输入、进程启动六部分。使用纯 Go 实现；正常构建关闭 CGO，不依赖钥匙串、Xcode 或 C 编译器。

插件不实现加密算法，不处理秘密原文，不把 agent 当作同步协调器。一个 agent 只要能运行 CLI，就能使用核心能力。

## 5. Google 授权：已核对的事实与接入建议

事实：

- Google 支持桌面应用 OAuth、PKCE 与 loopback 回调。
- `drive.file` 是非敏感、按文件授权的范围，可访问应用创建或用户明确提供的文件，无需申请整盘读取权限。
- External OAuth 应用处于 Testing 时，包含 Drive 权限的刷新令牌通常 7 天后过期。安装文档需要引导配置合适的发布状态；发布状态不等于应用已验证，也不保证令牌永不失效。
- `gws` 提供 Drive 操作与认证，但项目明确注明不属于 Google 官方支持产品，仍可能有不兼容变更。

建议：首版 CLI 直接通过成熟 OAuth 库调用 Drive API，不强制用户先安装 gws 或 gcloud。原因是用户没有现有 CLI 配置，而本工具只需要少量固定 Drive 操作。同步后端保留接口，将来可增加其他实现。

一次性接入流程：

1. 在个人 Google Cloud 项目启用 Drive API、配置 OAuth consent 和 Desktop 客户端。
2. 各设备复用同一个 OAuth 应用配置，分别完成浏览器授权，不复制其他设备的刷新令牌。
3. CLI 请求 `drive.file`，在 Drive 创建可见的 Keyenv 文件夹；该 scope 限制应用能访问的文件，不是“只能访问一个文件夹”的权限。
4. 保存明确的 vault ID、folder ID 和账户/应用绑定；同一应用跨设备发现库的行为必须实测。不能按文件夹名称唯一匹配，也不能在找不到库时默默新建。
5. 当前原型 OAuth token 仅在进程内保存，每次运行重新浏览器授权。持续登录留待后续：可评估由主密码加密的独立本机令牌文件，但必须先设计启动顺序、刷新原子写入和恢复；不能只存入需 Google 登录后才能下载的远端库，也不能退回明文存储。
6. Google 登录失败返回 `AUTH_REQUIRED`；离线缓存仍可使用，但清楚报告同步受阻。若库尚无缓存，则无法离线运行。

用户只需个人 Gmail，不要求购买 Workspace。当前尚未配置 OAuth 客户端、完成授权或上传任何文件。

## 6. 加密与本机保存

建议采用成熟密码库构建版本化封装：

- 随机生成 vault 数据密钥；用主密码经过 Argon2id 派生的密钥封装它。参数、随机盐及格式版本保存在库描述中。
- 数据使用认证加密，例如 AES-256-GCM；为每次加密生成新的随机 nonce。vault ID、格式版本及对象 ID 与密文绑定，拒绝跨库替换。
- 加密整个条目，包括名称、用途、字段映射、秘密和普通配置。云端文件名仅使用随机对象 ID；云端仍能观察大小、数量和写入时间。
- 本机缓存与上传暂存均为密文；主密码和解封的数据密钥只保留在当前进程内，不写入钥匙串、配置、参数或环境变量。Google OAuth token 当前也仅存内存。
- 解析不可信密文前限制长度、KDF 参数、对象数量；拒绝未知格式、认证失败、缺失父版本或损坏对象，不把损坏解释为可离线回退的网络故障。
- 使用系统随机数和成熟库，不自行编写密码算法。具体库版本、KDF 性能参数和文件格式需要独立评审及测试向量，尚未定稿。

主密码由用户自己保管，每次独立执行需要解密的命令时隐藏输入。没有自动解锁、跨命令缓存或后台解锁服务；用户不在场的 agent 暂时无法自行解锁。程序尽力清理秘密字节，但不承诺 Go 运行时完全擦除内存副本。

忘记主密码且没有其他可用明文副本时，无法通过 Google 账号或本机登录恢复凭据。首版暂不承诺在线修改主密码和密钥轮换；需要改密码时采用显式迁移新库并重新接入设备的流程，不能宣称重封装就能让旧密码对历史密文失效。

## 7. 并发同步方案

不依赖整库文件的最后写入者获胜，也不把“上传前比较版本”当作原子并发控制。当前未验证 Drive v3 对所需条件写入的端到端保证。

建议每次修改创建一个新的、不可变的加密版本对象。库初始化描述固定；每个版本包含条目 ID、父版本 ID、完整条目状态、操作 ID 和设备 ID。客户端时间仅作展示，不决定覆盖顺序。

处理规则：

1. 修改前成功拉取可见远端版本；拉取失败时不接受新修改。
2. 同一设备用进程锁串行化修改和缓存更新。
3. 两台设备分别更新不同条目时，两份修改共存。
4. 两台设备从同一个父版本更新同一条目时，形成分支，保留两份；发现后禁止该条目的运行和导出。
5. `resolve` 在终端让用户选择版本或重新输入值，再写入同时引用双方父版本的新对象。agent 只展示脱敏元数据，不自动比较或决定秘密内容。
6. 停用也是一个版本；停用与更新并发时同样视为冲突，不自动重新启用。离线设备在拉取前可能继续使用旧版本，工具必须展示缓存使用状态。
7. 上传使用预生成 Drive 文件 ID，并在第一次尝试前保存加密待上传对象与操作 ID；超时后重用同一文件 ID。遇到 409 时读取并验证已有对象内容，不能直接假定成功。
8. 上传后拉取验证；单个对象上传成功只代表该版本已保存，不代表其他设备已同步或绝无并发分支。
9. 如果检查联网后在提交阶段断网，保留加密待上传记录并报告 `PENDING_UPLOAD`，下次 `sync` 可重试；这属于失败恢复，不开放普通离线编辑。未确认版本不能作为已同步的默认运行版本。

首版数据量小，每次按 vault 文件夹分页枚举并下载缺失对象，完成校验后原子更新本机快照。有截止时间、有限重试和退避；列表未完整读取不能标记同步成功。

这是最终一致方案：能保留并发修改并在双方可见后识别冲突，不能保证每次命令拿到全球即时最新状态。任何“已同步”文案必须说明最近成功拉取时间与待上传数量。完整同步也不能证明另一设备此刻没有正在提交。

## 8. 备份、停用与能力边界

- 暂不删除远端历史版本；它们有助于解决冲突，但不是独立备份。
- 提供导出完整加密备份的设计入口，包含库描述和版本对象；恢复仍需主密码。首版要求验证备份能脱离 Drive 恢复到本机缓存，恢复到新云库的流程后续补充。
- 停用只影响本工具后续使用，不会撤销服务商 token、终止已启动进程，或收回已导出的 .env。
- 当前命令退出结束本次解锁，不会收回已经传给子进程或导出的值。
- 按命令注入减少泄露面，但子进程仍能读取、打印或发送环境变量；不提供对拥有完整本机执行权限的 agent 的强隔离。
- 工具自己的日志和结构化输出不含秘密；不能保证任意被启动程序的输出都不含秘密，也不承诺通用日志脱敏。
- 云端接入仍需要独立的 Google 授权与解锁材料供应方案，首版不自动同步主密码或向 Cloud Codex 发布凭据。

## 9. 实现前验证与验收

先做三个小原型，使用测试数据，不导入真实 token：

1. **Drive 授权与文件操作**：在两个独立客户端授权同一 Gmail；验证同应用 `drive.file` 发现、上传、下载、分页和授权撤回。验证预生成 ID 的超时重试与内容核验。记录 OAuth 配置步骤；不声称令牌永久有效。
2. **手动主密码**：验证隐藏输入与确认、跨进程重新解锁、错误密码、非终端拒绝、文件不含明文、拒绝覆盖，以及无 CGO 的 macOS 构建。真实 Mac 终端体验仍需本机验证。
3. **并发与缓存模型**：受控制造双客户端同条目冲突、不同条目并发、同名新增、停用并发、部分列表、延迟可见、上传成功但响应丢失和缓存中断写入；两份修改不能消失。

核心测试还需覆盖：错误主密码、密文被篡改、过大 KDF 参数、格式迁移拒绝、秘密字段不出现在 JSON/日志、环境变量精确注入、dotenv 转义和文件权限、子进程信号及退出状态，以及独立加密备份恢复。

目前已有加密、同步模型、Drive HTTP 适配器和手动主密码原型，自动化验证范围见 [验证记录](keyenv-validation.md)。正式 CLI 命令、macOS 与实际 Drive 验收尚未完成。
