判断

当前的主要问题不是插件包数量，而是一个工作流跨越了多个彼此不解释的权限、界面与运行环境。用户必须知道该去消息服务、账户预览页、密钥服务、CLI 还是本机 bridge，而且界面没有提供“现在已经能做什么、下一步还缺什么”的连续反馈。

推荐以 Miles Works 作为统一工作台和面向用户的产品名称；保持已有 miles-works 安装标识与部署端点。统一导航、默认设置、身份命名和状态语言，先把现有两个服务做成一个能连续完成的流程。单 MCP 入口、统一账户授权、云端唤起都需要技术实验；视觉整合本身不能证明这些已经成立。

首次连接完成消息交接。密钥只在任务需要时单独审阅。后台接收在用户选择设备与固定会话后开启。减少用户选择的是内部 ID、重复配置和不必要概念；保留的是实际授权范围、持续运行和高敏数据流向的知情确认。

信息架构

工作台主导航：收件箱、助手与连接、密钥、共享资料。账户区域：我的 Space、设备与接收、安全与撤销。Space 选择只影响当前消息和资料视图；密钥是账户级，页面始终标注账户范围。切换工作台 Space 绝不悄悄改已有助手授权。原型收件箱标为账户所有者视图；不能把所有者的管理可见性授给普通助手，也不能将定向消息误称为所有成员广播。

  • 收件箱：列表＋详情＋回复、云端保存与接收进度；高级回执、提交 ID 和审计进入详情，不占一级导航。
  • 助手与连接：按助手归组，显示具体宿主／设备、消息连接、密钥访问、接收方式和最近观察；主助手为角色标记。
  • 密钥：条目名称／用途／字段名、连接所获范围与撤销；默认不展示值；真正新增、修改值采用独立安全输入界面或本机 CLI，不鼓励聊天传值。
  • 我的 Space：列出账户全部 Space，明确进入或选择发送目标；新增 Space、接入助手为目标能力。
  • 设备与接收：设备有哪份凭据、接收在哪里运行、固定哪个会话、最近一次实际检查、未知通知与恢复入口。
  • 安全与撤销：区分浏览器退出、消息连接撤销、密钥连接撤销、本机服务卸载、服务商密钥轮换。

手机采用单列消息列表与详情，返回按钮保留筛选和阅读位置。导航允许横向滚动，账户操作不消失；高敏同意页保持完整、无需横向滚动。

关键设计决策

  • 默认合理但不假造权限：新用户在授权确认页看到“创建个人空间与独立助手身份”；确认后组合创建。已有账户复用其默认 Space，但显示可改的名称。登录本身不偷偷安装程序或扩大权限。
  • 每台设备默认独立连接、独立收取进度。重复安装应恢复同一绑定或明确创建新绑定，不能无限生成同名身份；现有 Actor／Consumer 组合恢复 API 需要技术设计。首次不让用户选择 Actor/Consumer。
  • 第一次只做消息。宿主若同时弹出 keys 连接，明确“可稍后连接”；不能因为一个安装包里有两服务而强迫全部授权。
  • 消息授权不做多组虚假的权限勾选，只显示准确成员能力；高敏资料需要隔离 Space。密钥默认全部关闭，任务建议条目可突出显示，但不能静默勾选授权。
  • “全部条目，包含未来新增”放高级展开区，并在最终摘要中醒目重复其范围。读和改可以独立选择；创建能力不隐含读取其他已有条目；当前实现会授予连接对自己新建条目的读写许可，实际调用仍受请求的 keys:read／keys:write scope 限制。
  • 背景接收采用渐进设置：消息往返确认后才询问，目标设备、固定会话、持续运行与凭据能力一起确认。默认按需检查，不把 MCP 自动描述成常驻接收。
  • 统一结果语言：保存、唤起、接收、处理分别呈现。缺少观测数据显示“无法确认／上次检查时间”，不从最后发信时间推断在线。
  • MCP 管理先做“创建意图＋浏览器批准”提案：模型能准备 Space 与连接请求；账户管理凭据不进入模型。最终协议由技术研究验证，不能为追求零点击而直接授账号级管理权。
  • 撤销的实际范围先写清。消息、keys、bridge 可能是三份独立凭据；“撤销这台设备全部访问”必须逐项执行、逐项记录，不是一个未实现的原子承诺。

换机／重新安装／已有账户

从账户找到已有 Space；沿用同一服务部署和身份历史，但新设备建立独立连接。能通过稳定设备标识恢复则提示“恢复原连接”，不能稳定识别则显示候选设备名称，由用户确认。默认不复用另一个设备的 Consumer，以免抢走其独立收取进度。会话授权过期只重做必要认证，不删除密钥、旧消息、bridge 账本或所有宿主配置。

本机 Keyenv 的本地加密存储、Google Drive 授权和远端 keys 是两条不同路径。新机器没有本机 Keyenv 时，不能静默把用户迁到远端；需要本机执行的高敏任务先解释存储和执行位置，再提供当前受支持的本机安装流程。不会因 keys 已上线而自动导入所有旧条目。

默认 Space、默认助手与收件规则

  • 默认 Space：首次准备“个人空间”；后续先恢复账户的明确默认选择，没有则使用上次成功选择。授权请求内固定并展示 Space，切换 UI 选择不能在请求之间串线。当前 selected_space 是浏览器会话选择，不应冒充账户持久偏好字段。
  • 默认助手：首次按“宿主 · 设备”准备独立身份；不把 Owner 当助手，也不让多个设备共享进度成为暗中默认。可以让用户把已验证身份标为主助手，但该设置不扩大权限、不自行改变连接默认收件人。
  • 默认收件人：沿用服务的用户入口；连接详情中可明确修改。回复始终显式指定收件人，稳定 request_id 的重试保持最初保留的目标。改变默认路由不重写旧消息或旧提交。
  • 所有 Space 发信：账户列表可以每行发起，发送表单始终显示 Space 与收件人。先选 Space，再解析其中身份；切 Space 清除旧收件人。普通助手仍受自己的 Space 凭据约束。
  • 管理型 MCP：目标支持提出创建 Space、准备身份／连接意图及查询自己的请求状态；不给普通助手账户 cookie、owner key 或任意签发工具。新增授权走账户批准界面。原型展示意图和批准，不宣称现有 MCP 具备能力。

发送、接收、处理与错误恢复

正常发送与回复

账户进入任意已有 Space → 选择该 Space 活跃收件人 → 填主题与正文 → 显示实际发送对象及资料范围 → 发出后确认“已存入云端”。网络响应丢失时使用同一个 request_id 查询原结果，不能换 ID 当作新消息重发。用户看到“正在确认发送结果”，直到确认保存或确定未提交。回复维持明确收件人、原线程和引用；成员不在该线程时转新消息并解释。

桥接通知仅带已验证消息引用；接收助手再次通过自己的凭据读取。可靠保存输入后提交 received；处理结果保存后提交 processed。若外部业务失败，报告实际失败，不把 processed 写成业务成功。消息中的外部指令不能自行扩大宿主权限或自动取得新密钥。

本机接收设置

选择当前设备 → 确认接收程序来源和可用版本 → 选择固定会话 → 明确持续运行、30–60 秒左右检查与独立成员凭据 → 安装后测试“发现引用／唤起会话／助手读取”三段。用户可暂停、恢复与卸载；暂停不撤销连接，撤销凭据不删除历史数据；更新保留 state_dir 和未知投递记录。更换会话需先处理旧绑定，不能把旧队列静默改投。当前 main 未提供统一桌面控制程序或远程工作台控制接口，原型设置按钮明确为模拟。

错误／状态该说什么可执行下一步不能做什么
OIDC 回调失败登录没有完成，显示安全错误阶段与请求关联回宿主重开，保留非敏感草稿输出 callback 参数、token、Google 响应或用户 claims
需要近期登录为变更授权重新确认身份；配置仍保留重新登录后恢复请求并再次展示范围自动批准新范围，或无限重登循环

429／5xx／断网保存结果仍待确认，稍后重查遵守 Retry-After 和退避；保留幂等标识生成新 ID 重复提交，或把离线数据说成最新
本机休眠／程序停止云端消息已保存，本机接收暂停查看具体设备、恢复原程序和原账本宣称消息丢失，重装并清空全部状态
Codex 会话关闭／绑定改变旧目标当前不可用核对固定会话，显式迁移绑定按消息内容选择任意命令、会话或权限
通知结果未知已尝试，但无法确认先 reconcile 原会话标记；找不到仍保留未知自动重发，或把无标记当作未投递证据
独立确认未投递允许人工重新入队，提示重复风险记录操作者与决定，再发一次一键把所有 unknown 清空重发
CURSOR_SCOPE_CHANGED需要重新扫描授权范围重置扫描游标，保留稳定 item 去重账本删除本地数据库／让所有历史消息重新唤起

部分撤销失败哪些成功、哪些仍待确认逐项重查实际 grant，再提示剩余动作把部分成功显示为设备全部访问已关闭

撤销与泄露

浏览器退出只结束浏览器会话。消息连接撤销只阻止该连接后续访问。keys 授权撤销只阻止其后续读取或修改。bridge 往往有独立凭据，应单独撤销和停服务。宿主已读取的消息、密钥与模型上下文不可被此产品远程收回；怀疑密钥泄露需要在实际服务商轮换。老式 owner key 与 legacy 连接不能假定因账户解绑就全部失效，迁移时必须盘点并单独处理。

密钥旅程

任务提出需要调用某 API → 助手先使用允许的元数据寻找条目，无法确定就请求用户选择 → 账户授权页显示真实客户端资源和条目范围 → 初始不勾选读、改、创建 → 用户选条目 → 最终摘要重复能力与数据流向 → 完成独立 OAuth → 宿主报告连接就绪 → 仅读取必要字段 → 值进入该工具结果／模型上下文 → 写入专用临时私密文件用于已授权任务并清理，日志、仓库和回复不含值。

原型不接触真实目录、不提供输入真实值的字段、不模拟实际取值。网页原生安全输入与本机 CLI 可以降低“聊天手填”暴露，但只要选择 fetch_entry，模型可见事实不变。本机“受控程序直接注入”属于另外一条架构，需要技术验证和审计，不能借当前 Skill 纪律声称实现了秘密对模型不可见。

权限是条目级，不是字段级。创建后，当前服务会在同一授权里增加新建条目的读写许可；仍受 OAuth 请求 scope 限制（keys/tools.rs:487）。这一点必须在创建权限摘要中说明。字段选择用于最少读取请求；授予条目读取后未来增加的字段也可能被该连接读取。条目所有权是账户级，和 Space 列表没有现成等价关系。跨 Space 使用同一账户密钥需要单独连接授权，不隐式继承 Space 成员资格。

视觉系统与组件合同

视觉方向：清楚、平静、有记录感。保留当前中性色与陶土色；弱化服务品牌之间的断裂，不做与现有产品完全无关的重新装修。纯文字 Miles Works 字标是提案；未挪用或重绘平台 logo。

44 个 token 和 12 个组件的源码、类型合同、真实状态示例与编译产物在 system/。基础卡涵盖品牌、灰阶、强调、语义色、标题、正文、标识、间距、触达、形状、焦点、动态效果。没有把字体系统的默认平台差异说成可精确跨设备一致。

组件核心状态／约束
Button主／次／强调／危险；悬停、焦点、禁用；真实写操作需提交中防重入
Field / SelectField / Choice可见 label；错误关联；不以 placeholder 代替 label；read/write 独立勾选
StatusTag / Notice文字和颜色同时表达；待核对不显示成功绿；突发阻断才使用 alert
Dialog原生 showModal、Esc、焦点约束、回到触发位置；高敏摘要再确认
NavigationItem / SpacePicker当前位置可被辅助技术读取；切换不改变已有授权
ConnectionRow身份、宿主、设备、授权、接收方式与观察时间分开；不伪造在线
PermissionSummary精确说明消息成员能力或密钥值进入模型的范围
DeliveryTimeline保存、通知、接收、处理四段；unknown 是独立可恢复状态

可访问性目标：WCAG 2.2 AA。主要正文与常规按钮对比至少 4.5:1；必要非文本控件和焦点至少 3:1。实际数值在 validation 中。点击目标 44 px 是本设计统一标准；最小辅助标签 12 px；支持 200% 缩放、320 px 视口、键盘导航与减少动态效果。尚未做真实读屏器、所有系统字体和所有语言覆盖验证，不使用“已完全无障碍”结论。

原型实际覆盖与未接入范围

已做可点击流程：选择 Codex／Claude／Grok、消息授权范围确认与防误批准、往返测试示意、消息列表／详情／筛选、发送与回复校验、账户多个 Space 发信入口、创建 Space 与 MCP 意图批准示意、按条目读／写／创建／全部未来条目密钥摘要、密钥拒绝与撤销、接收设置持续运行确认、unknown 找到／未找到标记与有依据的重新入队、退出与独立凭据撤销、手机消息返回与账户导航。

生产 API、登录跳转、真实目录、发送保存、真实往返测试、设备检测、bridge 安装与控制均未接入。原型所有动作是内存演示，刷新重置；密钥条目、助手、设备和消息均为合成。错误矩阵中 429、回调失败、真实 token 撤销等是实现合同，原型没有伪造已运行故障注入。原型不负责证明后端安全或 MCP 兼容。

给技术研究的精确问题

问题设计最低要求替代路径／失败仍可用
单 MCP 与增量同意消息先可用；keys 按需授权；工具资源和撤销边界准确保留两个 MCP，统一工作台串联；允许用户稍后连接 keys
浏览器账户复用复用人的身份不等于复用 agent 同意；__Host Cookie 边界不破坏第二服务需登录时提前说明缘由，保留原消息连接
新账号默认准备幂等创建 Space＋Actor/Consumer；失败可恢复，不重复留垃圾身份明确分步创建并保留状态；高级 IDs 可隐藏但不伪造完成
多 Space 创建已有账户也能新增；配额、命名、并发与默认一致当前只支持首个 Space／绑定已有 Space，UI 如实显示
账户各 Space 发信每次解析并验证目标 Space 与收件人，记录人的发送身份先进入目标 Space 再发送；不把跨 Space 凭据给普通助手
MCP 创建 Space／连接意图请求、最近登录批准、幂等状态查询、取消／过期、绑定原宿主网页操作；未批准不签发；owner key 不进入模型
独立设备进度稳定恢复绑定，不重复创建／共享别机 Consumer新设备默认新助手身份；显式复用才共享
密钥授权更新缩权即时生效，旧 grant 不残留，元数据不能泄露未授权条目当前撤销后重连；页面保留所选范围供复审
无模型可见的密钥执行明确执行位置、注入边界、允许目的地与审计，另做攻击测试高敏任务走本机受控程序；当前 fetch 路径如实提示模型可见
bridge 安装和状态受信分发、逐设备状态来源、原账本保留、变更目标可审阅本地 CLI status；工作台显示“未连接设备状态”，不假在线
Grok / Claude 后台真正宿主中验证调度、MCP、审批、去重、重叠运行与失败恢复按需检查；网页手动收发；不承诺通知 SLA
撤销设备全部能力所有独立 grant 盘点、逐项结果和失败重查分别撤销，清楚列出仍有效能力

实施顺序与验收

第一阶段：统一壳、文案与现有账户流程。沿用两 MCP；修复初次账户／Space／助手准备的组合流程；默认隐藏内部 IDs。让授权完成、MCP 连通、往返成功、后台运行四种状态分开。验收新账户、已有账户、第二台设备、拒绝与请求过期五条完整路径；每条准确记录确认次数和失败恢复，不先承诺一个具体“零授权”数字。

第二阶段：统一工作台的发送与连接管理。账户下所有 Space 可进入；目标创建 API 是否新增由技术结论决定。发送有幂等和结果丢失恢复；路由变更保留 CAS；独立撤销可观察。密钥目录与授权管理先只做元数据；不要让浏览器拿到原本不该可读的值。

第三阶段：可选接收助手。优先 Codex 已支持固定会话路径，做本机受信安装／恢复向导。之后分别验证 Claude、Grok.com、Grok Bot 的能力。未知投递、重启保留账本、双进程锁、绑定改变、设备离线必须在真实边界通过。

第四阶段：单 MCP／MCP 管理能力。只有技术实验能证明 resource、同意、token、撤销和宿主兼容正确后再改变连接形态。若不成立，保留双服务也能交付完整、诚实、连续的体验。

产品验收任务：一名用户在新机器上独立完成首次消息交接；在另一设备恢复已有 Space；从账户选择第二个 Space 发给正确助手；在没有插件的 Grok 中判断自己当前能否连接；只授权调研密钥、不碰生产条目；设备休眠后找到原因并恢复；面对 unknown 选择核对而不是盲目重发；撤销后能准确说出哪些后续能力被阻断、哪些旧数据不能收回。记录完成率、时间、无意义重复输入、求助次数和误解，而不是只收“看起来更好”。

外部来源与方法限制

  • baoyu-design 源码与方法：真实样式取值、tokens／组件合同、编译检查、离线 review 与浏览器迭代。不是对其“等同 Claude Design”宣传的独立验证。
  • Codex MCP 官方说明：用来确认远程 MCP 和认证总体路径；本轮未运行 Codex 实例。
  • Claude Code MCP 官方说明：用来确认远程 MCP 与连接管理总体路径；未复测真实生产 Google 登录。
  • Grok Connectors、Grok Bot routines：确认产品入口不同；未把文档能力扩张为用户账户已开放或已通过兼容。

本机已有 baoyu 技能是上级任务提供的背景；本次 cloud 环境没有挂载用户 Mac 的技能目录。因此下载公开 Markdown 与少量编译辅助文件到隔离 scratch，阅读来源后运行仅写设计产物的编译器／检查器，没有执行外部安装脚本或访问用户本机。最终以这个检出基准、合成原型与实际本地验证为准。
